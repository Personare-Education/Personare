# Product

## Platform

web

(An Electron desktop app for Windows, macOS and Linux whose interface is web technology. A mobile client is planned but not started.)

## Users

Students in general, not tied to one country. Two situations matter equally:

- **The semester student** (undergraduate, graduate, master's, short courses), studying at their own computer, with PDFs, links, quizzes and flashcards from several subjects at once.
- **The exam candidate** (public-service exams, university entrance, residency) with one dated goal and a lot to memorize.

Both use it on their own computer, alone, usually daily. The product is in a closed beta: people get in with an activation code tied to a Google account.

## Product Purpose

Personare brings together everything a student studies and schedules each review for the day they would be about to forget it. The site's line: "Estude hoje o que você esqueceria amanhã." ("Study today what you would forget tomorrow.")

Success has two parts, with the habit first:
1. **The daily habit:** coming back every day and reviewing what is due. This is what keeps a user.
2. **Organization:** having all the study material in one place. This is the way in.

## Positioning

Spaced repetition applied to **every** study activity, not just flashcards. A PDF, a link and a quiz each come back on their own schedule, computed by the FSRS algorithm. A flashcard deck is scheduled card by card. All of it lives in one local desktop app that works without an account.

## Operating Context

- Hierarchy: **Program** (an area of study: a course, a degree, an exam) → **Module** → **Activity** (link, PDF, quiz, flashcard deck).
- When an activity is finished (a PDF read, a link visited, a quiz taken), the user rates how hard it was (again / hard / good / easy). FSRS (`ts-fsrs`) schedules its next review from that. Flashcards are rated one by one in a review session.
- The app can start with the operating system, minimized to the tray, and notify that day's reviews.
- A calendar of reviews, with optional sync to a dedicated Google Calendar.
- Quiz questions can be generated by an AI (ChatGPT, Claude, Gemini) as Markdown and imported. Anki decks (`.apkg`) can be imported.
- Content is Markdown with LaTeX math (KaTeX) and image attachments, written for academic material.

## Capabilities and Constraints

- **Local-first:** all data is in a local SQLite database. The app works fully offline and without signing in. A Google account is only needed for Calendar sync and Drive backup.
- **Backups:** an encrypted local backup file, plus an optional copy on Google Drive.
- **Soft-delete:** content with review history is never hard-deleted, so the FSRS history is preserved.
- **Privacy:** LGPD duties (account deletion, data export, explicit consent per Google scope).
- **Languages:** Brazilian Portuguese and English (i18next).
- **Terminology:** "Program" was chosen over "Card" so it does not collide with "Flashcard". The review entity is the `ReviewItem`, not the activity itself.
- **Open:** how multi-device sync will resolve conflicts. This is deliberately deferred until the mobile client starts.

## Brand Commitments

- Name: **Personare**.
- Logo: a 2×2 grid of rounded squares. Three are in the foreground color at rising opacity and the last is in the brand blue, a nod to the study heatmap. It is a placeholder, and the website uses the same drawing.
- Brand blue: `#3b6cf6`, shared with the website (personare-website).
- Each Program has its own color and icon, chosen by the user.

## Product Principles

1. **Today first.** The most important thing at any moment is what is due now. Everything else supports coming back and doing it.
2. **Every activity can be remembered.** Scheduling is not a flashcard feature; it covers whatever the student studies.
3. **The student's own material, on their own machine.** It is local, works offline, and is never held hostage by an account.
4. **Show the system's reasoning.** When the app schedules something, the student should be able to see when and why, so the rating means something.
5. **Academic content is first-class.** Math, code and images render properly wherever content appears.
