# Personare

> Estude hoje o que você esqueceria amanhã. *(Study today what you would forget tomorrow.)*

Personare is a desktop app for students. It brings together everything a student studies (links, PDFs, quizzes and flashcard decks) and schedules each review for the day they would be about to forget it, using the [FSRS](https://github.com/open-spaced-repetition/ts-fsrs) spaced-repetition algorithm. Spaced repetition here covers **every** study activity, not just flashcards.

It is local-first: everything lives in a SQLite database on the student's computer and works offline, without an account. A Google account is only needed for the optional Calendar sync and Drive backup.

![Personare](images/demo.png)

See [`PRODUCT.md`](PRODUCT.md) for who it is for, the product principles and the brand.

## Features

- **Programs → Modules → Activities:** a program is an area of study (a course, a degree, an exam). Activities are links, PDFs, quizzes, flashcard decks and sequences, with optional unlock rules and module exams.
- **Two goals per program:** "Never forget" (long-term retention) or "Study for a test" (nothing comes due after the test's eve, with a countdown). See [`docs/architecture/scheduling.md`](docs/architecture/scheduling.md).
- **Today's reviews:** each activity comes back on its own FSRS schedule after the student rates it (again / hard / good / easy). A deck is scheduled card by card.
- **Calendar** of upcoming reviews, with optional sync to a dedicated Google Calendar.
- **Starts with the system**, minimized to the tray, and notifies the day's reviews.
- **Academic content:** Markdown with LaTeX math (KaTeX) and image attachments.
- **Imports:** Anki decks (`.apkg`), quiz questions and whole programs generated by an AI.
- **Claude integration (MCP):** a `.mcpb` extension lets Claude create programs, modules, activities and exams in the open app.
- **Backups:** an encrypted local file, plus an optional copy on Google Drive.
- **Gamification:** daily streak, points by season and ranks.
- Nine interface languages.

## Architecture

```
src/
├── main.ts            Electron main process: window, tray, updates, notifications
├── preload.ts         Bridges the oRPC MessagePort into the renderer (context isolation on)
├── database/          Drizzle schema, client and migrations runner (main process only)
├── ipc/               oRPC procedures by domain (programs, modules, activities, review, …)
├── actions/           Renderer-side wrappers that call those procedures
├── routes/            TanStack Router pages (file-based; routeTree.gen.ts is generated)
├── components/        React components (components/ui is shadcn/ui)
├── localization/      i18next setup and the locale files
├── main/              Main-process helpers: Anki import, OAuth, MCP bridge, updater
├── mcp/               The MCP server shipped in the .mcpb extension
├── utils/             Pure logic shared by both sides (FSRS, scoring, streak, …)
└── tests/             unit/ (Vitest) and e2e/ (Playwright, against the packaged app)
drizzle/               Versioned SQL migrations generated by drizzle-kit
docs/specs/            One spec per change, with its acceptance criteria
```

The database only exists in the main process. The renderer reaches it through oRPC procedures, so everything the UI does goes through a typed, validated IPC call.

## Development

Requires Node.js 20 or later (CI runs on 24).

```bash
npm ci          # install dependencies
npm run start   # run the app in development
```

| Script | What it does |
| --- | --- |
| `npm run check` / `npm run fix` | Lint and format (Ultracite/Biome) |
| `npm run test:unit` | Unit tests (Vitest) |
| `npm run test:e2e` | End-to-end tests against the packaged app (run `npm run package` first) |
| `npm run package` / `npm run make` | Package the app / build the installers |
| `npm run build:mcp` | Build the `.mcpb` Claude extension |
| `npx drizzle-kit generate` | Generate a migration after changing `src/database/schema.ts` |

Read [`CONTRIBUTING.md`](CONTRIBUTING.md) before opening a PR: it covers the method (spec first, then a failing test), branch and commit conventions, and the checks to run.

## Releases and updates

The **Publish Release** workflow builds the installers for Windows, macOS and Linux and publishes them, with the `.mcpb` extension, to [`personare-releases`](https://github.com/Personare-Education/personare-releases). The app checks the backend's update feed on start, on the stable or pre-release channel picked in Settings. Changes are listed in [`CHANGELOG.md`](CHANGELOG.md).

## macOS

The release ships a `.dmg` and a `.zip` for Apple Silicon (`arm64`) and Intel (`x64`) Macs, built on GitHub's macOS runners (see [`docs/specs/macos-build.md`](docs/specs/macos-build.md)); they can't be built on Windows or Linux.

> [!WARNING]
> The app is only signed ad hoc, not with an Apple Developer ID, and isn't notarized. So:
> - The first time it is opened, macOS blocks it ("Apple could not verify…"). Open it once, then go to **System Settings → Privacy & Security** and click **Open Anyway**.
> - If macOS says the app "is damaged and can't be opened", it is the download quarantine refusing an app without a Developer ID. After moving it to Applications, run in Terminal: `xattr -cr /Applications/Personare.app`
> - Auto update doesn't work on macOS: Squirrel.Mac only installs signed updates. Download new versions from the Releases page.
>
> Signing and notarizing need an [Apple Developer Program](https://developer.apple.com/programs/) membership.
